# Private data and security reports

Do not post secret calendar URLs, tokens, signing keys, private appointment screenshots or unsanitized device logs in public issues.

For a suspected vulnerability, use the repository's private vulnerability reporting feature if its owner enables it. Otherwise contact the maintainer through a private channel before sharing exploit details. No report destination or response-time guarantee is established yet.

If a calendar URL was exposed, reset its secret iCal address in Google Calendar and update every authorized client. Removing it from the latest Git commit does not remove it from public history.

This is experimental software, not a security-audited production service.
